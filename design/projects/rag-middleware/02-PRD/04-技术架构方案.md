## 一、技术选型总览

基于产品定位（Agent 应用的 RAG 中间件/插件，本地 Web 控制台 + API），技术选型遵循以下原则：

1. **MVP 优先**：首版聚焦核心链路，不追求分布式扩展
2. **轻量依赖**：减少外部服务依赖，优先自包含方案
3. **可替换**：每个环节提供抽象层，允许用户替换具体实现
4. **本地优先**：默认本地部署，支持远程向量库
5. **多语言 SDK**：优先 Python SDK（AI 生态），次推 TypeScript SDK

## 二、向量数据库选型

### 2.1 候选方案对比

| 维度 | Chroma | Qdrant | Weaviate | Milvus | Pinecone |
|------|--------|--------|----------|--------|----------|
| **协议** | Apache 2.0 | Apache 2.0 | BSD-3 | Apache 2.0 | 闭源 SaaS |
| **自托管** | ✅ | ✅ | ✅ | ✅ | ❌ |
| **查询延迟(p50)** |  varies | ~4ms | ~10ms | ~6ms | ~8ms |
| **混合搜索** | 基础 | 强 (BM42) | 最强 | 是 | 原生支持 |
| **规模天花板** | <10M vectors | 10M-1B | 10M-500M | 100M-10B+ | <50M 推荐 |
| **内存占用** | 低 | 中 | 中 | 高 | 无（托管） |
| **多模态支持** | 基础 | 基础 | 模块生态 | 基础 | 基础 |
| **LangChain 集成** | 原生 | 原生 | 原生 | 原生 | 原生 |
| **部署复杂度** | 极低 | 低 | 中 | 高 | 无 |

### 2.2 推荐选型

**默认向量库：Qdrant**

理由：
1. **性能优异**：p50 延迟 ~4ms，在开源方案中最快
2. **功能平衡**：混合搜索（BM42）、稀疏向量、二进制量化、HNSW + payload 过滤
3. **部署轻量**：单二进制/Docker 即可运行，不需要 Kubernetes
4. **Rust 编写**：内存安全、无 GC 停顿，生产稳定
5. **允许热切换**：作为默认库，提供标准抽象接口，用户可无缝切换

**备选方案**：
- Chroma：开发阶段/原型验证时使用（更低门槛）
- Weaviate：需要强大多模态混合搜索时
- Milvus：超大规模（>100M vectors）场景
- Pinecone：完全不想运维时（SaaS）

### 2.3 向量库抽象层设计

```
┌─────────────────────────────────────────┐
│          向量库抽象接口层                │
│  (统一 CRUD、检索、元数据过滤、切换)      │
├─────────────┬─────────────┬─────────────┤
│   Qdrant    │   Chroma    │  Weaviate   │  ...
│   (默认)    │  (开发备选)  │ (混合搜索)   │
└─────────────┴─────────────┴─────────────┘
```

## 三、Embedding 模型选型

### 3.1 候选方案

| 模型 | 维度 | 多语言 | 多模态 | 许可 | 适用场景 |
|------|------|--------|--------|------|----------|
| text-embedding-3 (OpenAI) | 1536 | ✅ | ❌ | API | 通用、英文优先 |
| BGE-M3 (BAAI) | 1024 | ✅ | ⚠️ | 开源 | 中文优化、混合检索 |
| E5 (Microsoft) | 1024 | ✅ | ❌ | 开源 | 通用、长文本 |
| Cohere Embed | 1024 | ✅ | ❌ | API | 商业场景 |
| CLIP (OpenAI) | 512 | ✅ | ✅ | 开源 | 图片+文本 |
| nomic-embed-text | 768 | ✅ | ❌ | 开源 | 轻量、本地部署 |
| GTE (Alibaba) | 768 | ✅ | ❌ | 开源 | 中文优化 |

### 3.2 推荐选型

**默认 Embedding：BGE-M3（BAAI）**

理由：
1. **中文效果最佳**：在中文语义检索 benchmark 上持续领先
2. **多语言支持**：中英日德法等 100+ 语言
3. **开源免费**：Apache 2.0，本地部署无成本
4. **混合检索**：同时输出 dense + sparse + colbert 表示
5. **尺寸适中**：1024 维，平衡精度与存储

**多模态 Embedding：CLIP / Chinese CLIP**
- 图片+文本统一向量空间
- 支持图片检索、图文跨模态搜索

**Embedding 服务架构**：
```
本地推理（onnxruntime / transformers）
    ↓
轻量 HTTP 服务（默认端口，自动启动）
    ↓
Embedding 抽象层 → 可替换为 OpenAI/Cohere API
```

## 四、LLM 选型与路由

### 4.1 LLM 集成策略

不做自研 LLM，提供**模型路由层**：

| 类型 | 模型/服务 | 用途 |
|------|----------|------|
| 生成模型 | GPT-4o / Claude 3.5 / 国内模型 | 最终答案生成 |
| 轻量模型 | GPT-4o-mini / 本地小模型 | 简单任务（分片策略推荐、意图分类） |
| 重排序模型 | Cohere Rerank / BGE Reranker | 检索结果重排序 |
| 多模态模型 | GPT-4o Vision / Qwen-VL | 图片理解 |

### 4.2 LLM 路由设计

```
用户查询
    ↓
意图识别（轻量模型）
    ↓
路由决策
├── 简单检索 → 本地小模型 / 规则引擎
├── 复杂推理 → GPT-4o / Claude 3.5
├── 多语言查询 → 对应优化模型
└── 图片理解 → 多模态模型
```

## 五、文档分片（Chunking）策略

### 5.1 分片策略矩阵

| 策略 | 适用文档 | 特点 | 配置参数 |
|------|----------|------|----------|
| **固定长度** | 通用 | 最简单，按字符/Token 切分 | chunk_size, chunk_overlap |
| **语义分片** | 长文章、论文 | 按语义边界切分，保留上下文 | 语义相似度阈值 |
| **递归分片** | 结构化文档 | 按标题层级递归切分 | 层级分隔符（#, ##） |
| **段落分片** | 报告、合同 | 按段落/自然段切分 | 段落分隔符 |
| **表格分片** | Excel/CSV/表格 | 按行/列切分，保留表头 | 表头保留策略 |
| **代码分片** | 代码仓库 | 按函数/类/块切分 | AST 解析 |
| **多模态分片** | 含图/表/视频的文档 | 文本+图片/表格分别提取 | 模态识别阈值 |

### 5.2 智能分片策略推荐引擎

```
文档输入
    ↓
文档类型识别（文件扩展名 + 内容 sniff）
    ↓
推荐分片策略
├── PDF 论文 → 语义分片 + 固定长度 fallback
├── Word 合同 → 段落分片 + 递归分片
├── Markdown 文档 → 递归分片
├── Excel/CSV → 表格分片
├── 图片/PPT → 多模态分片（OCR + 图片描述）
├── 视频 → 关键帧提取 + 音频转文本
└── 混合文档 → 分区域识别 + 组合策略
```

### 5.3 语义拆解程度配置

提供"拆解粒度"滑块/选项：

| 粒度 | chunk_size | 适用场景 |
|------|-----------|----------|
| 粗粒度 | 2000-4000 tokens | 快速概览、目录级检索 |
| 中粒度 | 500-1000 tokens | 平衡精度与召回 |
| 细粒度 | 100-300 tokens | 精确事实检索 |
| 自适应 | 动态 | 根据内容密度自动调整 |

## 六、召回策略设计

### 6.1 召回策略清单

| 策略 | 说明 | 适用场景 |
|------|------|----------|
| **Top-K 相似度** | 向量搜索最相似的 K 个 chunks | 通用场景 |
| **前后 chunks 扩展** | 检索命中 chunk 的前后各 N 个 chunks | 需要上下文的问答 |
| **同页/同节 chunks** | 检索命中 chunk 所在页面/章节的所有 chunks | 需要完整上下文的文档 |
| **多路召回** | 向量检索 + 关键词检索 + 知识图谱并行 | 复杂查询 |
| **重排序优化** | 初步召回后，用 reranker 精排 | 高精度需求 |
| **多向量库并行** | 同时查询多个向量库，LLM 融合结果 | 知识库隔离场景 |
| **路由召回** | 按查询意图路由到不同知识库/向量库 | 多 Agent/多领域 |
| **上下文压缩** | 检索后压缩冗余信息，保留精华 | 长上下文 LLM 限制 |

### 6.2 召回策略配置面板设计

```
召回策略配置
├── 基础检索
│   ├── 检索方式：向量搜索 / 混合搜索 / 关键词搜索
│   ├── Top-K 数量：5 / 10 / 20 / 自定义
│   └── 相似度阈值：0.5 / 0.7 / 0.9 / 自定义
├── 上下文扩展
│   ├── 前后扩展 chunks：0 / 1 / 2 / 3
│   └── 同页/同节扩展：关闭 / 开启
├── 多路召回
│   ├── 向量库选择：主库 / 库A+库B / 全部
│   ├── 路由策略：自动路由 / 手动指定
│   └── LLM 结果融合：关闭 / 开启
├── 重排序
│   ├── Reranker：关闭 / BGE / Cohere
│   └── Top-N 输出：3 / 5 / 10
└── 高级
    ├── 元数据过滤：字段条件
    └── 自定义权重：向量/关键词/时间 权重配比
```

### 7.2 核心模块设计

#### 7.2.1 知识库治理模块

```
知识库 (Knowledge Base)
├── 文档集合 (Document Collection)
│   ├── 文档属性标签（自定义字段）

├── 知识库版本管理

│   ├── A/B 版本对比
│   └── 版本发布/灰度
├── 权限控制 (RBAC)
│   ├── 知识库级别权限
│   ├── 文档级别权限
│   └── 操作级别权限（读/写/管理）
└── 知识库 LLM 路由配置
    ├── 绑定 Embedding 模型
    ├── 绑定向量库
    └── 绑定召回策略模板
```

#### 7.2.2 流程监控与可视化模块

```
RAG 流程可视化
├── 文档摄入流水线 (Ingest Pipeline)
│   ├── 上传 → 解析 → 分片 → 嵌入 → 索引
│   └── 每个环节的耗时、状态、错误日志
├── 检索流水线 (Retrieve Pipeline)
│   ├── 查询 → 意图识别 → 路由 → 召回 → 重排序 → 生成
│   └── 每个环节的耗时、命中 chunks、相似度分布
├── 实时看板
│   ├── QPS、延迟(p50/p99)、错误率
│   ├── 检索命中统计（命中率、Top-K 分布）
│   └── 向量库状态（文档数、向量数、索引状态）
└── 历史追溯
    └── 单次检索的完整链路回放
```

#### 7.2.3 质量与反馈模块

```
错题本 (Retrieval Failure Log)
├── 自动记录
│   ├── 检索返回空结果
│   ├── LLM 评分低的答案
│   └── 用户显式标记"不满意"
├── 错题分析
│   ├── 召回阶段问题（漏召、错召）
│   ├── 排序阶段问题（好答案排后面）
│   ├── 生成阶段问题（答案与检索内容不匹配）
│   └── 根因分类统计
├── 改进建议
│   ├── 分片策略调整建议
│   ├── 召回策略优化建议
│   └── 知识库补充建议
└── 闭环追踪
    ├── 问题确认 → 策略调整 → 重新验证 → 效果对比
    └── 改进效果量化（错题复测通过率）
```

## 十、关键技术风险

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| 文档解析质量差 | 高 | 集成多种解析器（marker、unstructured、自研），根据文档类型选择最佳方案 |
| 分片策略一刀切 | 高 | 提供多种策略 + 智能推荐 + 效果对比 |
| 检索召回不准 | 高 | 多路召回 + 重排序 + 错题本持续优化 |
