## 一、项目概述与产品定位

### 1.1 产品定位

**一句话描述：** 面向 Agent 应用的 RAG 插件/中间件——提供可视化的向量存储与检索召回基础设施层。

**核心定位：**
- 不是"知识库问答系统"，而是**Agent 应用的 RAG 基础设施**
- 核心价值：**让用户清晰看到系统中的 RAG 流程、配置、索引等全流程**
- 交付形态：本地 Web 控制台 + 标准 API，可嵌入任何 Agent 应用

### 1.2 运行方式

- **本地加载控制台**：Web 控制台本地部署/运行
- **服务形态**：可独立运行，也可作为模块嵌入现有系统
- **交付形式**：插件/中间件 + RESTful API 接口

### 1.3 目标用户

| 用户类型 | 特征 | 使用场景 |
|---------|------|---------|
| 个人开发者 | 独立开发 AI 应用 | 构建个人知识库 Agent、笔记助手 |
| 中小企业技术团队 | 有现有产品，需增强 AI | 客服系统、内部知识库智能检索 |
| 开发团队/AI 初创 | 构建多 Agent 系统 | Agent 记忆管理、多知识库路由 |

### 1.4 核心价值主张

> **可视化 RAG 全流程 + 灵活 API 调用**

- **可视化**：RAG 全流程可视化监控（ingest → chunk → embed → index → retrieve → rerank → generate）
- **可配置**：多种分片策略、召回策略、向量库切换
- **可集成**：标准 API，快速接入现有 Agent 系统
- **可治理**：知识库版本、权限、淘汰策略

### 1.5 功能清单（JiaWen 确认版）

#### 知识库治理
- 文档属性标签
- 文档淘汰策略
- 文档输入管理
- 权限控制
- 知识库版本管理

#### 智能分片与处理
- 智能分片策略（多种分片策略配置）
- 多模态支持：文档中的图片、表格、视频等均可 RAG 检索
- 语义拆解程度配置

#### 可视化与监控
- 可视化文库
- 检索命中统计
- 流程监控（RAG 流程可视化）
- 召回配置
- 检索算法配置

#### 质量与反馈
- 错题本（记录检索失败案例）
- 质量检测与反馈机制

#### 召回策略（重点）
- 多种召回策略配置：匹配前后三个 chunks、同页 chunks 等
- 知识库 LLM 路由到不同向量库进行匹配
- 结合知识库索引进行拆解的问题，多匹配几个向量库同时进行检索召回，然后 LLM 分析
- 切换向量库

#### API 与集成
- API 管理
- 快速调用接口：知识上传存储、检索匹配、切换向量库等
- AI 助手提供一站式指引

#### 目标市场估算（TAM/SAM/SOM）

| 维度 | 估算值 | 说明 |
|------|--------|------|
| **TAM（总可触达市场）** | 36.8亿美元（2025） | 全球 RAG 软件/平台市场 |
| **SAM（可服务市场）** | 5.5~9.2亿美元 | 面向中小企业和个人开发者的 RAG 基础设施层 |
| **SOM（可获得市场）** | 0.5~1.0亿美元（3-5年） | 假设占据 SAM 的 5-10% |

#### 区域市场分布

| 区域 | 2025年规模 | 占比 | 增速特征 |
|------|-----------|------|---------|
| 北美 | 6.5亿美元 | 41.5% | 最大市场，企业级需求旺盛 |
| 欧洲 | 5.1亿美元 | 32.5% | GDPR 合规驱动私有部署 |
| 亚太 | 4.4亿美元 | 26.0% | **增速最快**，中国/日本/印度活跃 |
| 其他 | — | — | 快速增长但基数较小 |

### 2.2 技术趋势

#### 六大关键技术趋势

1. **从"单一向量检索"到"多路混合召回"**：Hybrid Search（向量+关键词+知识图谱）已成为基础设施标配，重排序成为标准环节

2. **多模态 RAG 崛起**：文档中的图片、表格、视频均可检索，Vision-Language 模型与 RAG 结合

3. **Agentic RAG**：RAG 从被动检索进化为主动决策，Agent 自主决定检索策略、路由到不同知识库

4. **向量数据库分层与专业化**：
   - 小规模（<10M）：Chroma/pgvector
   - 中大规模（10M-1B）：Qdrant/Weaviate/Pinecone
   - 超大规模（>1B）：Milvus/Vespa
   - 市场正在出现"统一抽象层"需求

5. **可观测性与评估体系成熟**：RAGAS、DeepEval、Promptfoo 等质量评估框架；LangSmith、LangFuse 等可观测性工具

6. **本地/私有部署偏好上升**：约 **27.6%** 选择 On-Premise/Hybrid，EU AI Act、NIST AI Framework 推动可解释、可追溯的 RAG 系统

### 2.3 发展现状

#### 市场发展阶段

当前处于 **"早期采用者向早期大众过渡"** 阶段：
- ~80% 的企业 AI 项目 2025 年未走出 POC 阶段
- 从"实验性"转向"生产级部署"——稳定性、安全、可观测性要求显著提高
- 头部玩家集成 RAG 到云 AI 栈，但中小企业和个人开发者仍需要轻量独立方案

#### 市场六大痛点

1. **工具碎片化严重**：需拼接 5+ 工具搭建完整 RAG 链路
2. **分片策略黑盒**：一刀切分片，无法针对文档类型智能适配
3. **召回质量不可控**：缺乏可视化调试手段
4. **多模态支持薄弱**：图片、表格、视频 RAG 检索能力普遍不成熟
5. **缺乏质量反馈闭环**：检索失败案例无法被系统学习
6. **向量库锁定**：选择后难以切换，缺乏统一抽象层

#### 机会窗口

| 机会点 | 我们的切入点 |
|--------|------------|
| 一站式 RAG 控制台 | Web 控制台本地加载，统一管理全流程 |
| 智能分片 | 多种分片策略 + 语义拆解程度配置 |
| 召回策略可视化 | 流程监控 + 召回配置面板 |
| 多向量库切换 | 知识库 LLM 路由到不同向量库 |
| 质量反馈 | 错题本 + 质量检测机制 |
| 多模态 RAG | 图片/表格/视频均可检索 |

## 五、技术架构与实现方案

### 5.1 技术选型

| 组件 | 首选方案 | 备选方案 | 选型理由 |
|------|----------|----------|----------|
| **向量数据库** | Qdrant | Chroma, Weaviate, Milvus | 性能优异（~4ms p50）、混合搜索、部署轻量、Rust 稳定 |
| **Embedding** | BGE-M3 (BAAI) | OpenAI API, E5, GTE | 中文最佳、多语言、混合检索、开源免费 |
| **API 层** | FastAPI (Python) | Go + Gin | Python 生态丰富、AI 集成便捷 |
| **前端** | React + TypeScript | Vue3 | 生态成熟、可视化库丰富 |
| **元数据数据库** | SQLite（开发）→ PostgreSQL（生产） | MySQL | SQLite 零配置起步，PostgreSQL 生产级 |
| **文档解析** | unstructured + marker + pdfplumber | 自研 | 多解析器覆盖不同格式 |
| **任务队列** | Celery + Redis | RQ, 线程池 | 成熟可靠 |
| **部署** | Docker Compose | K8s | 一键启动，降低门槛 |
| **SDK** | Python SDK（首版） | TypeScript SDK（后续） | Python 是 AI 生态主流 |

### 5.3 召回策略设计

| 策略 | 说明 | 适用场景 |
|------|------|----------|
| Top-K 相似度 | 向量搜索最相似的 K 个 chunks | 通用场景 |
| 前后 chunks 扩展 | 命中 chunk 的前后各 N 个 chunks | 需要上下文的问答 |
| 同页/同节 chunks | 所在页面/章节的所有 chunks | 需要完整上下文的文档 |
| 多路召回 | 向量检索 + 关键词检索 + 知识图谱并行 | 复杂查询 |
| 重排序优化 | 初步召回后 reranker 精排 | 高精度需求 |
| 多向量库并行 | 同时查询多个向量库，LLM 融合 | 知识库隔离场景 |
| 路由召回 | 按查询意图路由到不同知识库/向量库 | 多 Agent/多领域 |
| 上下文压缩 | 检索后压缩冗余信息 | 长上下文 LLM 限制 |

## 六、商业模式与定价策略

### 6.1 核心策略：开源核心 + 云服务 + 企业增值

```
开源社区版（获客漏斗）
    ↓ 自然转化
云托管版（转化变现）
    ↓ 需求升级
企业版/专业版（高客单价）
```

### 6.2 三层产品定义

#### 开源社区版
- 完整 RAG 核心引擎
- Web 控制台（单用户）
- 基础召回策略
- 基础 API
- **限制**：单用户、无知识库治理、无高级召回
- **许可**：Apache 2.0

#### 云托管版
- 开源版所有功能
- 多用户协作（3-20人）
- 知识库版本管理
- 托管向量库
- 优先技术支持
- **不包含**：私有部署、SSO、高级审计

#### 企业版/专业版
- 云托管版所有功能
- **本地/私有部署**（数据不出域）
- **SSO / SAML / LDAP**
- **细粒度 RBAC**
- **审计日志**（1年+）
- **99.9% SLA**
- **专属技术支持**
- **定制开发**

### 6.3 云托管版定价

| 套餐 | 价格 | 目标用户 | 规格 |
|------|------|----------|------|
| **Free** | ¥0/$0 | 个人开发者试用 | 1 知识库、500MB、1,000 API 次/月 |
| **Starter** | ¥99/$15/月 | 个人开发者/小项目 | 5 知识库、5GB、10,000 次/月 |
| **Pro** | ¥499/$79/月 | 中小企业技术团队 | 20 知识库、50GB、100,000 次/月、完整 RBAC |
| **Business** | ¥1,999/$299/月 | 中型企业/开发团队 | 无限知识库、200GB、500,000 次/月 |
| **Enterprise** | 定制报价 | 大型企业 | 私有部署、SSO、SLA、定制开发 |

### 6.4 收入预测

| 收入来源 | Year 1 | Year 2 | Year 3 |
|----------|--------|--------|--------|
| 云托管订阅 | ¥36万 | ¥360万 | ¥1,680万 |
| 企业版授权 | ¥20万 | ¥150万 | ¥600万 |
| **合计** | **¥56万** | **¥510万** | **¥2,280万** |

### 6.5 关键定价决策

1. **开源版功能完整**：限制在多用户/治理/企业功能，核心 RAG 能力不阉割
2. **企业版提供买断选项**：买断价 = 3 年年费，赠送 1 年维护
3. **支持国内模型/向量库**：作为本土化差异化优势

## 七、风险分析与应对策略

### 7.1 技术风险

| 风险 | 概率 | 影响 | 应对措施 |
|------|------|------|----------|
| 文档解析质量不稳定 | 高 | 高 | 多解析器策略、质量评分、人工校对入口 |
| 分片策略一刀切效果差 | 高 | 高 | 智能推荐、A/B 测试、错题本驱动 |
| Embedding 推理性能瓶颈 | 中 | 中 | ONNX 量化、异步批处理、GPU 可选 |
| 向量库迁移风险 | 中 | 中 | 抽象层设计、多库并行、迁移工具 |
| 多模态技术不成熟 | 中 | 中 | 渐进支持、降级策略、Beta 标注 |

### 7.2 市场风险

| 风险 | 概率 | 影响 | 应对措施 |
|------|------|------|----------|
| 市场需求验证失败 | 中 | 高 | MVP 快速验证、用户访谈、灵活调整 |
| 巨头入场挤压 | 高 | 中 | 差异化定位（本地+可视化）、开源壁垒、垂直深耕 |
| RAG 范式转移（长上下文） | 低-中 | 高 | 定位升级为"知识管理"、成本优势、多模态/Agent |

### 7.3 竞争风险

| 风险 | 概率 | 影响 | 应对措施 |
|------|------|------|----------|
| 开源社区增长不及预期 | 中 | 高 | 预热+Demo+文档+社区运营 |
| 竞品快速跟进 | 高 | 中 | 速度壁垒、深度壁垒、社区壁垒 |

### 7.4 执行风险

| 风险 | 概率 | 影响 | 应对措施 |
|------|------|------|----------|
| 技术实现难度超预期 | 中 | 高 | MVP 裁剪、技术评估、模块化 |
| 资金/资源不足 | 中 | 高 | 快速收费、开源获客、控制成本 |

### 7.5 合规风险

| 风险 | 概率 | 影响 | 应对措施 |
|------|------|------|----------|
| 数据隐私合规 | 中 | 高 | 本地优先、加密、审计、合规声明 |
| 开源许可风险 | 低 | 高 | 许可审计、优先宽松许可、法律审查 |

## 八、实施路线图

### 8.1 Phase 1：MVP（2-3 个月）

| 模块 | 功能 | 优先级 |
|------|------|--------|

| API | 知识库 CRUD、文档上传、基础检索 API | P0 |
| 本地部署 | Docker Compose 一键启动 | P0 |

| 召回策略 | 多种召回策略配置面板、重排序 | P1 |
| 流程监控 | RAG 流水线可视化、检索日志 | P1 |
| 错题本 | 检索失败记录、根因分析 | P1 |
| 多向量库 | 向量库抽象层、切换能力 | P1 |

### 8.3 Phase 3：专业版（3-4 个月）

| 模块 | 功能 | 优先级 |
|------|------|--------|

| 多模态 | 图片/表格/视频检索 | P2 |
| 知识库路由 | LLM 自动路由到不同向量库 | P2 |
