# 目标用户需求分析

**项目：** RAG 中间件/插件
**调研人：** Mery（CIO）
**日期：** 2026-06-02

---

## 一、用户群体划分

基于产品定位（Agent 应用的 RAG 中间件/插件），目标用户分为三大群体：

```
目标用户
├── 个人开发者（Solo Developer）
├── 中小企业技术团队（SMB Tech Team）
└── 开发团队/AI 初创（Dev Team / AI Startup）
```

---

## 二、个人开发者（Solo Developer）

### 2.1 用户画像

| 维度 | 描述 |
|------|------|
| **人口特征** | 25-35 岁，独立开发者、自由职业者、技术爱好者 |
| **技术背景** | 全栈开发能力，熟悉 Python/Node.js，对 AI 有兴趣但非专家 |
| **使用场景** | 构建个人项目、开源工具、学习实验、接外包单 |
| **典型项目** | 个人知识库助手、笔记应用 AI 增强、小众领域的问答机器人 |
| **决策因素** | 免费/低成本、易上手、文档完善、社区活跃 |
| **付费意愿** | 低，偏好开源免费；愿意为"节省大量时间"付小额订阅 |

### 2.2 典型场景与痛点

**场景 1：构建个人知识库 Agent**
> "我想做一个能读我的笔记和收藏文章，然后回答我问题的个人助手。"

| 痛点 | 现状 | 期望 |
|------|------|------|
| 拼接工具太麻烦 | 需要同时学向量库、Embedding API、LLM API、Prompt 工程 | **一站式 RAG 控制台** |
| 不知道分片对不对 | 文档切分成 chunks 后效果差，不知道怎么调 | **可视化分片效果 + 智能推荐** |
| 检索不准 | 明明文档里有答案，但检索不到 | **召回策略可调 + 错题本记录** |
| 想换向量库试试 | 用了 Chroma 想试 Qdrant，迁移麻烦 | **一键切换向量库** |

**场景 2：为开源项目集成 RAG**
> "我的开源工具需要文档问答功能，但不想自己造轮子。"

| 痛点 | 期望 |
|------|------|
| 需要轻量嵌入 | 提供 SDK 或 API，几行代码集成 |
| 不引入重依赖 | 可以独立部署，不影响主项目 |
| 有社区支持 | 遇到问题能快速找到解决方案 |

### 2.3 需求优先级

| 需求 | 优先级 | 说明 |
|------|--------|------|
| 本地一键部署 | P0 | Docker Compose 一键启动 |
| 可视化控制台 | P0 | 不用写代码就能配置 RAG |
| 免费使用核心功能 | P0 | 开源或免费 tier |
| 详细文档 + 示例 | P0 | 降低学习成本 |
| API 集成 | P1 | 嵌入自己的应用 |
| 多模态支持 | P2 | 图片/视频检索是加分项 |
| 高级召回策略 | P2 | 个人项目不需要太复杂 |

## 三、中小企业技术团队（SMB Tech Team）

### 3.1 用户画像

| 维度 | 描述 |
|------|------|
| **人口特征** | 30-45 岁，技术负责人/全栈工程师/后端工程师 |
| **团队规模** | 3-20 人技术团队 |
| **技术背景** | 有现有产品（SaaS、内部系统、客服系统），需要增加 AI 能力 |
| **使用场景** | 为现有产品增加知识库问答、客服增强、内部文档检索 |
| **典型项目** | 产品文档助手、内部知识库、客服机器人、HR 政策问答 |
| **决策因素** | 稳定性、集成便捷性、成本可控、数据安全 |
| **付费意愿** | 中等，愿意为"节省开发时间 + 运维成本"付费 |

### 3.2 典型场景与痛点

**场景 1：产品文档问答**
> "我们的产品文档有 500 页，用户天天问重复问题，想做个文档问答机器人嵌入到帮助中心。"

| 痛点 | 现状 | 期望 |
|------|------|------|
| 没有专门的 AI 团队 | 团队忙于产品功能，没有余力研究 RAG | **开箱即用 + 低代码集成** |
| 数据安全顾虑 | 文档包含产品细节，不想上传第三方 | **本地部署/私有部署** |
| 检索质量不稳定 | 有时候答对，有时候胡说 | **质量监控 + 错题本 + 可调召回** |
| 需要效果可解释 | 被老板问到"为什么这个答案错了"，答不上来 | **RAG 流程可视化 + 命中统计** |

**场景 2：内部知识库**
> "公司内部有很多分散的文档（Wiki、PDF、PPT），新员工找不到信息。"

| 痛点 | 期望 |
|------|------|
| 文档来源多样 | 支持多种格式统一检索 |
| 权限控制 | 不同部门看不同内容 |
| 知识更新 | 文档改了，问答结果自动更新 |
| 版本管理 | 能回溯某个版本的知识库状态 |

**场景 3：客服系统增强**
> "客服团队被重复问题淹没，想先用 AI 过滤常见问题。"

| 痛点 | 期望 |
|------|------|
| 与现有系统集成 | 提供 API，嵌入现有客服工作台 |
| 回答可控 | 召回策略可调，避免答非所问 |
| 质量反馈 | 客服可以标记错误答案，持续优化 |

### 3.3 需求优先级

| 需求 | 优先级 | 说明 |
|------|--------|------|
| 本地/私有部署 | P0 | 数据安全是首要考量 |
| 稳定可靠的 API | P0 | 集成到现有系统 |
| 权限控制 | P0 | 不同用户看不同内容 |
| 检索质量可监控 | P0 | 知道 RAG 链路哪里出了问题 |
| 多种召回策略 | P1 | 提升回答准确率 |
| 知识库版本管理 | P1 | 企业级治理需求 |
| 错题本/反馈 | P1 | 持续优化 |
| 多模态支持 | P2 | 有 PDF 里的图片需要检索 |
| SSO/审计日志 | P2 | 合规需求 |

## 四、开发团队 / AI 初创（Dev Team / AI Startup）

### 4.1 用户画像

| 维度 | 描述 |
|------|------|
| **人口特征** | 25-40 岁，AI 工程师、ML 工程师、技术创始人 |
| **团队规模** | 5-50 人 |
| **技术背景** | 深入理解 LLM、向量搜索、RAG 原理，追求性能和控制力 |
| **使用场景** | 构建 AI 产品的基础设施层、多 Agent 系统、记忆系统 |
| **典型项目** | AI 助手平台、Agent 框架、记忆云服务、垂直领域 RAG 产品 |
| **决策因素** | 性能、扩展性、架构灵活性、API 设计质量 |
| **付费意愿** | 高，愿意为"节省工程时间 + 提升产品竞争力"付企业级费用 |

### 4.2 典型场景与痛点

**场景 1：多 Agent 系统的记忆/知识层**
> "我们的平台有 10+ 个 Agent，每个 Agent 需要不同的知识库，还需要共享记忆。"

| 痛点 | 现状 | 期望 |
|------|------|------|
| 知识库隔离 | 不同 Agent 需要隔离的知识库 | **知识库路由 + 权限隔离** |
| 向量库选型困难 | 不知道选 Qdrant 还是 Weaviate | **多向量库并行检索 + 效果对比** |
| 检索策略差异化 | 客服 Agent 和研发 Agent 需要不同召回策略 | **按知识库配置召回策略** |
| 性能瓶颈 | 高并发时检索延迟高 | **检索性能监控 + 优化建议** |

**场景 2：构建垂直领域 RAG 产品**
> "我们想做一个法律文档检索产品，需要极高的检索精度。"

| 痛点 | 期望 |
|------|------|
| 召回策略精细化 | 匹配法条上下文、同页条款、关联案例 |
| 分片策略专业化 | 法律文档的分片需要特殊逻辑 |
| 质量评估体系 | 需要系统化的检索质量评估 |
| 效果可 A/B 测试 | 不同召回策略的效果对比 |

### 4.3 需求优先级

| 需求 | 优先级 | 说明 |
|------|--------|------|
| 高性能 API | P0 | 低延迟、高并发 |
| 多种召回策略配置 | P0 | 不同场景需要不同策略 |
| 多向量库切换/并行 | P0 | 对比和灵活部署 |
| 可观测性/监控 | P0 | 生产环境必须 |
| 知识库 LLM 路由 | P1 | 智能路由到最佳知识库 |
| 语义拆解配置 | P1 | 控制分片粒度 |
| 错题本 + 质量检测 | P1 | 持续优化检索效果 |
| 多模态 RAG | P2 | 图片/表格/视频 |
| 版本管理 | P2 | 实验不同版本的知识库 |

## 五、三类用户需求对比

| 需求维度 | 个人开发者 | 中小企业 | 开发团队/AI 初创 |
|---------|-----------|---------|-----------------|
| **核心诉求** | 快速上手、免费 | 稳定可靠、数据安全 | 性能、灵活、可扩展 |
| **部署偏好** | 本地 Docker | 私有部署/本地 | 混合（开发本地、生产云） |
| **界面需求** | 越简单越好 | 直观够用 | 专业控制台 |
| **API 使用** | 偶尔 | 频繁 | 核心依赖 |
| **召回策略** | 默认够用 | 需要几种预设 | 高度自定义 |
| **知识库治理** | 不需要 | 需要基础版 | 需要完整版 |
| **多模态** | 加分项 | 偶尔需要 | 产品竞争力 |
| **付费意愿** | 低 | 中 | 高 |
| **支持渠道** | 社区/文档 | 工单/文档 | 专属支持 |
| **典型价格敏感度** | 月付<$20 | 月付<$500 | 月付<$5000 |

## 六、用户旅程地图

### 6.1 个人开发者用户旅程

```
发现 → 试用 → 集成 → 优化 → 推荐

发现：GitHub/Twitter/技术博客看到项目
  ↓ 吸引点：开源免费、一键部署、可视化

试用：Docker 一键启动，上传几篇文档测试
  ↓ 关键体验：5 分钟内看到 RAG 流程可视化

集成：用 API 嵌入个人项目
  ↓ 关键体验：SDK 简洁、文档清晰

优化：调整分片策略、召回策略，看效果提升
  ↓ 关键体验：错题本帮助发现问题

推荐：推荐给朋友/社区
  ↓ 驱动力：真正解决了问题
```

### 6.2 中小企业用户旅程

```
发现 → 评估 → 试点 → 推广 → 续约

发现：技术负责人搜索"本地部署的知识库 RAG 方案"
  ↓ 吸引点：本地部署、可视化、API 集成

评估：对比 LangChain/Dify/RAGFlow
  ↓ 关键决策：是否支持本地部署、是否提供 API、是否能看到 RAG 流程

试点：一个部门（如客服）试用 2-4 周
  ↓ 关键体验：检索质量可监控、错题本帮助优化

推广：扩展到更多部门/产品
  ↓ 关键体验：权限控制、版本管理满足治理需求

续约：持续使用并升级
  ↓ 驱动力：ROI 可量化（客服效率提升 X%）
```

## 七、需求提炼总结

### 7.1 共性需求（所有用户都需要）

1. **可视化 RAG 控制台**——清晰看到 ingest → chunk → embed → index → retrieve → generate 全流程
2. **简单部署**——Docker Compose 一键启动
3. **标准 API**——RESTful API 或 SDK，几行代码集成
4. **检索质量可监控**——命中统计、流程追踪

### 7.2 分层需求

| 层级 | 需求 | 主要服务用户 |
|------|------|------------|
| 基础层 | 文档上传、分片、嵌入、检索、API | 所有用户 |
| 进阶层 | 多种召回策略、多向量库切换、错题本 | 中小企业、开发团队 |
| 专业层 | 知识库版本管理、权限控制、淘汰策略、多模态 | 中小企业、开发团队 |
| 企业层 | SSO、审计日志、SLA、专属支持 | 中小企业、开发团队 |

### 7.3 北极星指标建议

| 指标 | 定义 | 目标 |
|------|------|------|
| 周活跃知识库数 | 每周有检索请求的知识库数量 | 持续增长 |
| API 调用成功率 | 检索 API 的成功响应比例 | >99% |
| 检索满意度 | 用户标记"有用"的比例 | >80% |
| 错题本闭环率 | 错题被优化解决的比例 | >50% |
| NPS | 用户推荐意愿 | >40 |
