## 二、新定位详解

### 核心定位
**RAG 向量存储与检索召回的基础设施层**

我们不是做一个"问答界面"，而是做一个让开发者可以**嵌入到自己 Agent 应用中的 RAG 引擎**。用户通过 Web 控制台管理和配置 RAG 流程，通过 API 将检索能力集成到自己的产品中。

### 运行方式
- **本地加载控制台**：Web 控制台本地部署/运行
- **服务形态**：可独立运行，也可作为模块嵌入现有系统
- **交付形式**：插件/中间件 + API 接口

### 目标用户
| 用户类型 | 特征 | 使用场景 |
|---------|------|---------|
| 个人开发者 | 独立开发 AI 应用，需要快速接入 RAG | 构建个人知识库 Agent、笔记助手 |
| 中小企业技术团队 | 有现有产品，需要增强 AI 能力 | 为客服系统、内部知识库增加智能检索 |
| 开发团队 | 构建多 Agent 系统，需要统一的记忆/知识存储 | Agent 记忆管理、多知识库路由 |

### 核心价值
> 让用户"清晰看到系统中的 RAG、配置、索引等流程"

- **可视化**：RAG 全流程可视化监控
- **可配置**：多种分片策略、召回策略、向量库切换
- **可集成**：标准 API，快速接入现有 Agent 系统
- **可治理**：知识库版本、权限、淘汰策略

## 三、功能清单（JiaWen 确认版）

### 知识库治理
- 文档属性标签
- 文档淘汰策略
- 文档输入管理
- 权限控制
- 知识库版本管理

### 智能分片与处理
- 智能分片策略（多种分片策略配置）
- 多模态支持：文档中的图片、表格、视频等均可 RAG 检索
- 语义拆解程度配置

### 可视化与监控
- 可视化文库
- 检索命中统计
- 流程监控（RAG 流程可视化）
- 召回配置
- 检索算法配置

### 质量与反馈
- 错题本（记录检索失败案例）
- 质量检测与反馈机制

### 召回策略（重点）
- 多种召回策略配置：匹配前后三个 chunks、同页 chunks 等
- 知识库 LLM 路由到不同向量库进行匹配
- 结合知识库索引进行拆解的问题，多匹配几个向量库同时进行检索召回，然后 LLM 分析
- 切换向量库

### API 与集成
- API 管理
- 快速调用接口：知识上传存储、检索匹配、切换向量库等
- AI 助手提供一站式指引

## 四、与"知识库问答系统"的核心差异

| 维度 | 原定位（问答系统） | 新定位（RAG 中间件） |
|------|-------------------|---------------------|
| 产品形态 | 完整的问答应用（前端+后端） | 中间件/插件（核心引擎+控制台） |
| 目标用户 | 终端用户直接使用 | 开发者集成到自己的产品中 |
| 核心价值 | 回答问题 | 提供可配置、可监控的 RAG 基础设施 |
| 交互界面 | 聊天对话界面为主 | Web 控制台（配置+监控）+ API |
| 竞争维度 | 问答质量、UI 体验 | 检索精度、召回策略、集成便捷性 |
| 技术重点 | 对话管理、Prompt 工程 | 向量存储、分片策略、多路召回 |

## 五、对后续工作的影响

### 1. 竞品分析方向调整
- 不再分析"问答产品"（如 ChatGPT、Perplexity）
- 聚焦分析 **RAG 框架/中间件**：LangChain、LlamaIndex、Dify、RAGFlow、FastGPT、AnythingLLM 等
- 重点对比：向量存储能力、检索召回策略、API 集成度、可视化配置

### 2. 技术架构调整
- 弱化"对话界面"设计
- 强化"控制台"设计：配置面板、流程监控、检索调试
- 强化 API 设计：标准 RESTful / SDK 接口

### 3. 商业模式调整
- 面向开发者付费，而非终端用户
- 可能采用：开源核心 + 商业插件、API 调用量计费、企业版授权
