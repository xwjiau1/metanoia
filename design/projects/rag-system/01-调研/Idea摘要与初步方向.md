## 一、Idea摘要

### 一句话描述
> 打造一款面向中小企业的「智能知识库对话系统」，让企业沉淀的知识文档能够通过自然语言对话被精准检索和引用，降低知识查找成本，提升信息获取效率。

### 核心洞察

企业每天都在产生海量文档，但这些知识资产大多处于"沉睡"状态：
- **85%** 的企业知识资产未被有效管理（IDC 数据）
- 平均每位员工每周浪费 **7+小时** 在信息检索和验证上
- 传统知识库依赖关键词搜索，召回率不足，无法处理语义层面的查询需求
- 大模型（LLM）虽然具备强大推理能力，但存在"幻觉"问题，无法直接用于企业知识问答

**RAG 技术的本质**：给大模型装上一个"外部知识大脑"——先检索企业私有文档中的相关内容，再基于检索结果生成回答，实现"有据可依"的智能问答。

### 市场机会

| 指标 | 数据 | 来源 |
|------|------|------|
| 全球企业知识库市场规模（2025） | 420亿美元 | IDC《全球AI知识库市场报告》 |
| 年复合增长率（CAGR） | 37% | IDC |
| 预计2033年市场规模 | 近420亿美元（RAG细分） | 行业预测 |
| 知识查询效率提升 | 90%+ | 企业落地实践数据 |
| 新员工培训周期缩短 | 40% | 企业落地实践数据 |

**结论**：市场处于高速增长期，RAG 技术从概念验证阶段加速迈入企业规模化部署阶段，存在明确的商业机会。

## 二、初步方向

### 2.1 产品定位

| 维度 | 定位 |
|------|------|
| **目标市场** | 中小企业（50-500人） |
| **核心场景** | 企业内部知识问答、客服知识库、培训资料查询 |
| **差异化** | 开箱即用、低成本部署、中文优化、引用溯源 |
| **竞争策略** | 避开与Dify/Coze等低代码平台正面竞争，聚焦"知识库问答"单一核心场景做到极致 |

### 2.2 核心功能方向（V1.0）

基于RAG系统的通用能力，结合竞品分析和用户痛点，确定以下核心功能方向：

#### P0（必须有）
1. **知识库管理**
   - 支持多种文档格式上传（PDF、Word、Excel、PPT、TXT、Markdown）
   - 文档分类和标签管理
   - 批量上传和自动解析
   - 文档版本管理（增量更新）

2. **智能问答**
   - 自然语言对话式问答
   - 多轮对话支持（上下文理解）
   - 引用溯源（显示答案来源文档和段落）
   - 答案可信度评分

3. **向量化检索引擎**
   - 自动文档分块和向量化
   - 语义检索（非关键词匹配）
   - 混合检索策略（语义+关键词）
   - 检索结果重排序

4. **用户权限管理**
   - 基础RBAC（管理员/编辑者/查看者）
   - 知识库级别权限隔离
   - 用户组管理

#### P1（重要）
5. **多模型支持**
   - 支持主流LLM（OpenAI、DeepSeek、ChatGLM等）
   - 模型切换和对比
   - 本地模型部署（Ollama集成）

6. **对话管理**
   - 对话历史保存
   - 对话收藏和分享
   - 对话导出（Markdown/PDF）

7. **系统管理**
   - 使用统计和分析
   - API接口开放
   - Webhook集成

#### P2（可选）
8. **协作功能**
   - 多人在线编辑知识库
   - 评论和反馈机制

9. **插件扩展**
   - 自定义工具调用
   - 第三方系统集成（飞书/钉钉/企业微信）

10. **多模态支持**
    - 图片解析和问答
    - 表格结构化提取

### 2.3 技术方向建议

| 技术层 | 建议方案 | 说明 |
|--------|----------|------|
| **Embedding模型** | BGE-M3 / text-embedding-3 | 中文语义理解效果好 |
| **向量数据库** | Milvus / Qdrant / Chroma | 开源、高性能、社区活跃 |
| **LLM** | DeepSeek-V3 / GPT-4o / Qwen | 平衡效果与成本 |
| **文档解析** | unstructured / marker | 支持复杂格式和OCR |
| **分块策略** | 语义分块 + 递归字符分块 | 保证上下文完整性 |
| **检索策略** | 多路召回 + 重排序 | 提升召回准确率 |
| **前端框架** | React + TailwindCSS | 技术部熟悉栈 |
| **后端框架** | Python(FastAPI) / Node.js | 需Irra确认 |
| **部署方式** | Docker Compose + SaaS | 支持私有化部署 |

> ⚠️ **技术选型需与Irra（CTO）确认后定稿**，以上为Mery基于市场调研的初步建议。

### 2.4 用户体验方向

1. **零配置开箱即用**：用户注册后5分钟内即可上传文档开始问答
2. **对话式交互**：类似ChatGPT的聊天界面，降低学习成本
3. **答案可验证**：每个答案都附带来源引用，点击可跳转原文
4. **渐进式权限**：免费版→专业版→企业版，按需升级

## 三、竞品初步分析

### 3.1 直接竞品

| 竞品 | 定位 | 优势 | 劣势 | 定价 |
|------|------|------|------|------|
| **Dify** | 低代码AI应用平台 | 工作流编排强大、多模型支持 | 文档解析弱、学习曲线陡、企业版贵 | 云服务免费/企业版收费 |
| **FastGPT** | 轻量级知识库问答 | 部署简单、中文优化、开源免费 | 功能较单一、复杂文档处理弱 | 开源免费/云服务付费 |
| **RAGFlow** | 企业级复杂文档处理 | 深度文档解析、多路召回精度高 | 部署复杂（16G+内存）、学习曲线陡 | 开源免费 |
| **AnythingLLM** | 全栈私有化方案 | 全本地化、200+格式支持、权限管理 | 桌面版为主、团队协作弱 | 开源免费 |
| **ChatWiki** | 企业AI问答智能体 | 多终端支持、操作简单 | 知名度低、生态较小 | 按需付费 |

### 3.2 差异化机会

1. **中小企业专属**：现有竞品要么面向开发者（Dify）、要么面向大企业（RAGFlow），缺少真正面向中小企业的"开箱即用"产品
2. **成本优化**：通过轻量架构设计，实现低成本硬件部署（目标：4核8G可运行）
3. **中文体验优化**：针对中文文档的解析、分词、检索优化
4. **引用溯源体验**：比FastGPT更直观的溯源展示，比RAGFlow更简洁的界面

## 四、用户画像初步

### 4.1 目标用户群体

| 用户类型 | 描述 | 核心需求 | 使用场景 |
|----------|------|----------|----------|
| **中小企业管理员** | 公司行政/IT负责人，负责内部系统选型 | 快速部署、低维护成本、权限管理 | 搭建公司知识库、员工自助查询 |
| **客服团队** | 电商/服务型企业客服主管 | 快速检索产品知识、统一回答口径 | 产品FAQ、售后问题解答 |
| **培训负责人** | 企业HR或培训经理 | 培训资料集中管理、新员工快速上手 | 员工培训、制度查询、操作手册 |
| **知识工作者** | 研发/产品/咨询等岗位员工 | 快速查找历史文档、技术资料 | 技术文档查询、项目资料检索 |

### 4.2 典型痛点

1. **"找文档太费劲"**：企业网盘/微信群/邮件里资料散乱，找不到想要的信息
2. **"答案不可靠"**：ChatGPT给的回答没有依据，不敢直接用于工作
3. **"上手门槛高"**：现有工具需要配置Docker、API Key、向量数据库，非技术人员搞不定
4. **"数据安全顾虑"**：敏感文档不敢上传到第三方平台，需要私有化部署

## 五、风险与应对

| 风险 | 等级 | 说明 | 应对策略 |
|------|------|------|----------|
| 技术实现复杂度 | 中 | RAG链路长（解析→分块→向量化→检索→生成），每个环节都影响最终效果 | MVP优先核心链路，逐步迭代优化 |
| 竞品市场成熟 | 中 | Dify、FastGPT等已有成熟开源方案，用户选择多 | 差异化定位中小企业，聚焦"易用性"和"成本" |
| 数据安全顾虑 | 高 | 企业敏感文档不愿上传第三方 | 主打私有化部署，数据不出本地 |
| 大模型幻觉问题 | 高 | 即使RAG也不能完全消除幻觉 | 强化引用溯源，设置置信度阈值，用户可反馈纠正 |
| 技术选型变更 | 低 | LLM/Embedding技术迭代快 | 模块化设计，支持模型热切换 |
