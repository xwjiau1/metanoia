## 一、产品定位

**一句话描述：**
> 一款面向《杀戮尖塔》系列玩家的 AI 实时攻略助手，通过截图识别当前游戏状态，结合完整卡牌数据库和流派知识，为玩家提供即时的对局决策建议、卡组分析和复盘记录。

**核心价值主张：**
- 对新手：不再卡关，每张牌都有"教练"解释该不该拿
- 对进阶：不再凭感觉，每个决策都有数据和策略支撑
- 对高阶：不再繁琐，一键记录整局、AI自动复盘

---

## 二、目标用户

| 用户群 | 占比 | 核心场景 | 功能侧重 |
|--------|------|---------|---------|
| 新手玩家 | 35%~40% | 学习中，频繁卡关 | AI问答、卡牌查询、基础教学 |
| 进阶玩家 | 35%~40% | 冲进阶，追求优化 | 选牌建议、路线分析、流派推荐 |
| 高阶玩家 | 15%~20% | 冲连胜、做内容 | 数据复盘、版本追踪、创作辅助 |

### 3.2 P0功能详细定义

#### P0-1：截图实时问答（核心差异化功能）

**功能描述：** 玩家截取当前游戏画面，上传至平台，AI识别游戏状态并回答玩家问题。

**用户故事：**
> 作为刚进入StS2的新手玩家，我在战斗中不确定这轮该怎么出牌，希望截图发给AI，AI能告诉我最优出牌顺序和原因，让我理解"为什么这么打"。

**验收标准：**
- [ ] 支持上传 PNG/JPG 截图，最大10MB
- [ ] AI能识别当前角色、回合、能量、手牌、敌人状态
- [ ] 对"这轮怎么打"类问题，给出具体的出牌顺序建议
- [ ] 对"这张牌抓不抓"类问题，给出拿/不拿的建议+理由
- [ ] 回答必须用中文，解释清晰易懂（新手也能看懂）
- [ ] 单次问答响应时间 ≤ 15秒（截图上传+识别+生成回答）
- [ ] 支持StS1和StS2两代游戏截图

**异常流程：**
- 截图模糊/非游戏画面：提示"未能识别游戏画面，请重新截取游戏窗口"
- AI无法确定最优解：坦诚告知"当前局势较复杂，以下是几种可行方案..."
- 截图包含Spoiler（未解锁内容）：正常回答，不做限制

---

#### P0-2：卡牌/遗物即时查询

**功能描述：** 快速查询任何卡牌或遗物的详细信息，包括效果、升级前后对比、适用流派、配合卡牌。

**用户故事：**
> 作为进阶玩家，我在商店看到一张不熟的牌，想快速查它的效果和常见用法，不想切出去翻Wiki。

**验收标准：**
- [ ] 支持按卡牌名称（中英文）、费用、类型、角色筛选
- [ ] 显示卡牌完整信息：名称、费用、类型、效果、升级后效果、角色归属、稀有度
- [ ] 显示"常见配合"：哪些卡牌/遗物与该牌有协同
- [ ] 显示"适用流派"：该牌常见于哪些流派构建
- [ ] 支持StS1和StS2两代数据，可切换查看
- [ ] 支持模糊搜索（如输入"祭品"可找到"Offering/祭品"）
- [ ] 响应时间 ≤ 2秒

---

#### P0-3：卡牌数据库（两代兼容）

**功能描述：** 完整的StS1和StS2卡牌数据库，支持浏览、搜索、筛选、对比。

**用户故事：**
> 作为想尝试新角色的玩家，我想查看StS2 Necrobinder的所有卡牌，了解她的机制和可能的流派。

**验收标准：**
- [ ] StS1：4角色全部卡牌（Ironclad、Silent、Defect、Watcher）
- [ ] StS2：5角色全部卡牌（Ironclad、Silent、Defect、Necrobinder、Regent）
- [ ] 每张卡牌包含：名称、费用、类型、效果、升级前后、稀有度、角色、版本归属
- [ ] 支持按角色、费用、类型、稀有度筛选
- [ ] 支持两张卡牌对比视图
- [ ] 数据随StS2版本更新同步更新

**数据规模估算：**
- StS1：约350张卡牌
- StS2：500+张卡牌（Early Access阶段持续增加）
- 合计：约900张卡牌

---

#### P0-4：敌人/BOSS数据库

**功能描述：** 完整的敌人信息库，包括血量、意图模式、技能、推荐对策。

**验收标准：**
- [ ] StS1和StS2两代敌人数据
- [ ] 每个敌人包含：名称、血量范围、意图模式、技能效果、推荐策略
- [ ] BOSS包含：阶段变化、特殊机制、各角色对策要点
- [ ] 支持按章节、类型筛选

---

#### P0-5：对局截图记录

**功能描述：** 玩家可在对局关键节点（选牌、路线选择、战斗前、战斗后）手动截图保存，形成对局时间线。

**用户故事：**
> 作为想提升自己的进阶玩家，我希望能记录每局的关键决策点，赛后回看自己哪里可以改进。

**验收标准：**
- [ ] 支持手动"记录当前画面"按钮（快捷键或界面按钮）
- [ ] 自动记录时间戳、当前章节、角色、进阶等级
- [ ] 以时间线形式展示一局中的所有截图
- [ ] 支持为每张截图添加文字备注
- [ ] 单局最多记录50张截图
- [ ] 本地存储优先，支持导出为 Markdown/图片集

### 3.3 P1功能详细定义（概要）

#### P1-1：路线选择建议
- 玩家截图地图界面，AI根据当前血量、卡组强度、需求推荐路径
- 输入：地图截图 + 简要状态（血量、金币）
- 输出：推荐路线 + 理由（缺牌→推荐精英/商店，低血量→推荐火堆）

#### P1-2：卡组流派分析
- AI自动识别玩家当前卡组，归类到已知流派（力量战、防战、毒贼、球机...）
- 输出：流派判定 + 核心牌到位率 + 缺少的关键牌 + 建议补充方向

#### P1-3：遗物组合推荐
- 查询某个遗物时，显示"常与XX遗物配合"、"注意与XX遗物的冲突"
- 输入玩家当前遗物列表，输出协同评分

#### P1-4：网络攻略自动同步
- 自动爬取StS2更新日志、社区讨论、Wiki更新
- AI生成"版本变更摘要"，推送用户关心的内容
- 详见技术架构文档

#### P1-5：AI自动复盘
- 基于对局截图时间线，AI逐节点分析决策质量
- 输出复盘报告：最优决策回顾、可改进点、与同角色胜率对比

---

### 3.4 P2功能详细定义（概要）

#### P2-1：联机模式策略
- StS2 4人联机专属策略建议
- 队友卡组协同分析、分工建议

#### P2-2：数据统计看板
- 个人胜率统计（按角色、进阶、流派）
- 抓取偏好分析（"你比平均水平更爱拿防御牌"）
- 对比匿名社区数据

#### P2-3：内容创作辅助
- 一键生成"卡组截图+数据面板"分享图
- 导出Markdown格式攻略文本
- 数据引用（"本卡组在进阶15胜率62%"）

## 四、呈现形式建议

### 4.1 推荐形态：**Web应用（桌面端浏览器）**

**理由：**
1. **切屏成本低**：StS在PC上玩时，Alt+Tab切到浏览器查询是最自然的操作
2. **截图方便**：桌面端截图（Win+Shift+S / Snipaste）后直接粘贴到Web页面上传
3. **开发成本低**：一套Web代码覆盖所有平台（Win/Mac/Linux），StS三平台玩家都能用
4. **AI能力易接入**：Web端直接调用Kimi API，无客户端集成复杂度
5. **更新即时**：Web应用无需用户下载更新，StS2版本变化时攻略同步即时生效

**补充形态（未来考虑）：**
- **浏览器插件**：悬浮窗形式，游戏中一键呼出（降低切屏成本）
- **移动端H5**：适配手机查询（玩家在通勤等非游戏时间浏览攻略）
- **桌面端Electron应用**：离线可用、快捷键截图、本地数据库（P2阶段）

### 4.2 界面架构建议

```
主界面（三栏布局）
┌─────────────────┬──────────────┬─────────────┐
│   左侧导航栏     │   中央内容区  │  右侧AI助手  │
├─────────────────┼──────────────┼─────────────┤
│ • 卡牌数据库    │              │ ┌─────────┐ │
│ • 敌人数据库    │   当前页面     │ │ 截图上传 │ │
│ • 我的记录     │   内容展示     │ │ 问答历史 │ │
│ • 流派指南     │              │ │ 输入框   │ │
│ • 版本更新     │              │ └─────────┘ │
│ • 设置        │              │             │
└─────────────────┴──────────────┴─────────────┘
```

**核心交互原则：**
- 截图上传区始终可见（右侧固定面板），一键粘贴上传
- 数据库浏览页支持"选中卡牌→发送到AI助手提问"的联动
- 移动端自动切换为单栏+底部导航

## 五、数据指标

### 5.1 北极星指标

**"周活跃提问用户数"（WAU-Q）**
- 定义：每周至少使用AI问答功能1次的用户数量
- 为什么是北极星：直接反映产品核心价值是否被用户认可
- 目标：M1 ≥ 500，M3 ≥ 2,000，M6 ≥ 5,000

### 5.2 辅助指标

| 指标 | 定义 | 目标值 |
|------|------|--------|
| 截图问答次均满意度 | 用户对AI回答点"有帮助"的比例 | ≥ 75% |
| 数据库查询日活 | 每日使用卡牌/遗物查询的UV | M3 ≥ 500 |
| 对局记录使用率 | 注册用户中使用过截图记录功能的比例 | ≥ 20% |
| 留存率 | 新用户7日/30日留存 | 7日≥30%，30日≥15% |
| 两代切换使用率 | 使用过多代数据切换功能的比例 | ≥ 40%（验证兼容价值） |
| 平均响应时间 | 截图问答从上传到显示答案的中位时间 | ≤ 12秒 |

### 5.3 负面指标（需监控）

| 指标 | 说明 | 告警阈值 |
|------|------|---------|
| AI幻觉率 | AI给出明显错误的卡牌效果/策略建议 | > 5% |
| 截图识别失败率 | 无法识别游戏画面的比例 | > 10% |
| 用户放弃率 | 上传截图后未等待回答就离开的比例 | > 20% |

## 六、非功能需求

### 6.1 性能
- 页面首屏加载 ≤ 3秒（3G网络下）
- 数据库查询响应 ≤ 2秒
- AI问答响应 ≤ 15秒（含截图上传、识别、生成）
- 同时在线用户支持 ≥ 1,000（初期目标）

### 6.2 兼容性
- 浏览器：Chrome ≥ 100, Edge ≥ 100, Firefox ≥ 100, Safari ≥ 15
- 支持StS1和StS2两代游戏截图识别
- 支持中文/英文双语查询（界面中文为主）

### 6.3 安全与隐私
- 用户截图仅用于AI识别，不用于模型训练（除非用户明确同意）
- 用户数据存储加密
- 无用户登录时支持匿名使用（限制每日问答次数）

### 6.4 可用性
- 支持快捷键粘贴截图（Ctrl+V 在截图上传区）
- 支持拖拽上传截图
- 移动端浏览器可用（基础查询功能）

## 八、风险与假设

### 8.1 关键假设
1. **用户愿意切屏使用**：假设PC玩家游戏时切到浏览器查询是可接受的行为
2. **截图识别可行**：假设当前OCR+视觉模型能准确识别StS游戏界面元素
3. **AI建议有价值**：假设LLM结合游戏数据库能给出"比凭感觉更好"的建议
4. **StS2持续火热**：假设Early Access期间玩家基数足够支撑工具使用

### 8.2 风险及缓解

| 风险 | 影响 | 缓解措施 |
|------|------|---------|
| AI幻觉给出错误策略 | 高 | 建立"卡牌效果事实核查"层；对不确定答案标注"仅供参考" |
| StS2版本频繁变动 | 中 | 自动化数据同步+社区众包审核 |
| 截图识别准确率低 | 高 | 先支持文字输入作为fallback；持续优化视觉识别 |
| 用户量不足 | 中 | MVP阶段先做社区传播，与UP主合作引流 |
| 竞品跟进 | 低 | 先发优势+社区壁垒+数据积累 |
