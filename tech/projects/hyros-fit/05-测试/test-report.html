发现问题清单

[已修复] ISSUE-001 — CalendarScreen 缺少函数导入（运行时错误）

位置： screens/CalendarScreen.js

问题： onDayPress 中调用了 getWorkoutLogByDate，但未在文件顶部 import。运行时调用会直接抛出 TypeError: getWorkoutLogByDate is not a function，导致日历日期详情功能完全不可用。

修复： 在 import 语句中添加 getWorkoutLogByDate。

[已修复] ISSUE-002 — CalendarScreen 今日安排 day_index 不匹配（逻辑错误）

位置： screens/CalendarScreen.js 的 getTodayPlanDay()

问题： new Date().getDay() 返回 0-6（周日=0），但计划创建时 day_index 按 0-6 对应周一到周日。导致日历"今日安排"显示的肌群永远错位（例如周一显示周日的训练内容）。

修复： 将 getDay() 转换为以周一为0的索引： (new Date().getDay() + 6) % 7。

[已修复] ISSUE-003 — ProfileScreen 退出登录导航失效（功能失效）

位置： screens/ProfileScreen.js

问题： 退出登录后调用 navigation.replace('Login')。由于 Login Screen 仅在 userToken == null 的分支中注册，当前处于已登录分支的 Stack 中不存在 Login route，replace 动作可能无法冒泡到父 Stack Navigator，导致用户停留在原页面或导航异常。

修复： 使用 navigation.getParent()?.navigate('Login') 或改用全局状态触发 App 重新渲染。MVP中简化为 navigation.navigate('Login') 让导航冒泡处理，并确保 App 层级监听 token 变化。

[已修复] ISSUE-004 — CreatePlanScreen uid 为空时崩溃风险

位置： screens/CreatePlanScreen.js 的 handleCreate

问题： const uid = await AsyncStorage.getItem('userToken') 可能返回 null，parseInt(null) 得到 NaN，传入数据库会导致插入失败或不可预期行为。

修复： 添加 guard clause：若 !uid 则 Alert 提示并返回。

[已修复] ISSUE-005 — WorkoutLogScreen 空状态缺失

位置： screens/WorkoutLogScreen.js

问题： 当 planDayId 缺失时，页面无任何提示，用户看到空白页面。

修复： 在渲染区域添加空状态提示：若 !planDayId 则显示"未选择训练日"的引导文案。

[已修复] ISSUE-006 — HomeScreen 导入未导出函数（潜在运行时风险）

位置： screens/HomeScreen.js

问题： 导入了 getActivePlan 但该函数在 database/operations.js 中不存在。虽然当前代码未实际调用此函数（使用了 allPlans.find 替代），但多余的未解析导入在某些打包环境下可能引发问题。

修复： 移除未使用的 getActivePlan import；在 operations.js 中补充 getActivePlan 函数定义以备将来使用。

[已确认 — MVP限制] ISSUE-007 — 密码明文存储

位置： database/operations.js 的 createUser

问题： 密码以明文形式存储在 SQLite 中，存在安全风险。

说明： MVP 阶段接受此限制。V1.1 应引入 bcrypt 或至少 SHA256 哈希。

[已确认 — 性能优化项] ISSUE-008 — WorkoutLogScreen 每次输入触发数据库更新

位置： screens/WorkoutLogScreen.js 的 handleUpdateSet

问题： 用户在重量/次数输入框每输入一个字符都触发 updateWorkoutSet 数据库写操作，快速输入时造成不必要的 I/O。

说明： MVP 阶段功能正常，不影响可用性。V1.1 应引入 debounce 批量写入。

[已确认 — 架构改进项] ISSUE-009 — 多步数据库操作无事务保护

位置： database/operations.js 的 deletePlan、setActivePlan

问题： deletePlan 执行3条 DELETE，setActivePlan 执行2条 UPDATE，均无事务包裹。中间失败会导致数据不一致。

说明： MVP 阶段概率极低（本地SQLite，单用户）。V1.1 应使用 db.withTransactionAsync 包裹。
